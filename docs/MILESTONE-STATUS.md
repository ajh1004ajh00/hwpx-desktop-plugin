## 2026-09-14 추가: 실제 표 셀·부분 실패·복구 삭제

Sites 비공개 버전 7: 소스 `44683c006344f600b64c3867b658504536dd4e85`. 검색 셀 경로 수정본이며 사용자 작업 탭은 재로드하지 않았다.

- #4·#27: 검색한 표 셀의 글자 크기/굵게가 적용되지 않는 문제를 재현했다. upstream 검색 이동은 flat 셀 위치만 설정하지만 native 서식 명령은 cellPath를 사용해 빈 경로로 끝났다. 고정 빌드 overlay에서 경로를 보존하도록 수정했다. 회귀 검사는 수정 전 실패, 수정 후 통과했다.
- #6·#7: 격리한 로컬 내장 브라우저에서 직접 만든 2×2 표를 WebMCP로 작성했다. 셀 0/1 성공 후 셀 2의 커서를 이동해 오래된 명령을 거부했고, 앞의 성공 내용과 셀 3은 유지됐다. 셀 2만 새로 검색/확인해 수정하고 동일 요청 재시도에도 한 번만 적용됨을 확인했다. 이전 filechooser timeout과 별개로 실제 여러 셀의 기본 흐름을 검증했다.
- #27·#7: 수정 빌드에서 셀 3의 '일정 유지'만 10→16pt, 굵게 true 적용. 다른 셀은 10pt/굵게 false 유지. Undo 1회로 굵게만 false, 16pt 유지. 서식 변경 전 snapshot의 쓰기는 거부됐다. 화면 조작과 모델 결과 검사이며 사람 시각 판정/PDF 검사는 아니다.
- #8: 합성 표를 새 탭에서 복구했다. 해당 검증 origin(127.0.0.1:4190)의 복구 후보를 UI에서 삭제하고 새 탭으로 재진입해 복구 대화상자 없이 빈 1문단/표 0 문서를 확인했다. 이전 페이지 snapshot을 새 페이지에 전달한 쓰기도 거부됨. 사용자 Sites 복구 기록은 건드리지 않았다. 프로세스 강제 종료·OS 재부팅은 아직 미실행이다.
- #13: 기본 테스트 46개 통과 및 새 런타임 빌드 성공. 설치 캐시와 원격 CI는 별도다.
- #26: native 벤치마크에 응답마다 샘플링한 RSS/heap과 process.resourceUsage().maxRSS 기록 추가. 이번 단일 프로세스 수명 최대 RSS 230,891,520바이트(문서 생성 및 두 방식 모두 포함). 캐시 사용 순회 샘플 RSS 최대 97,841,152바이트, WASM 할당 5,963,776바이트. 브라우저 peak/캐시의 메모리 절감 인과 증거로 해석하지 않는다.
- #21·#24: 현재 CUA tab capability는 pageAssets/webmcp뿐이며 네트워크/캐시 타이밍 측정을 제공하지 않는다. 실제 Sites 전송량/업데이트 캐시 증거는 미확보다. 파일 크기나 로컬 no-store를 Sites 실측으로 대신하지 않았다.

남은 자동 작업은 실제 host 네트워크/캐시 계측, 종료/재부팅 복구, 더 복잡한 표·객체/보호 범위, 브라우저 peak 메모리, 최종 제출 트리의 원격 CI/설치본 검증이다. 아래 절은 이전 작업 기록이며 본 절의 추가 결과로 보완한다.

## 후속 자동 작업: 시험 문서와 분석 비용

분석 재사용 개선은 Sites 버전 5로 비공개 배포 완료했다. 소스 `108bcef18233e8eb30c33b20ff85ab36f7f5df74`, 배포 `appgdep_6aa77cab9900819197427f3ca239845c`, 상태 succeeded. 사용자 작업 탭을 재로드하지 않았으며 아래 버전 4 기록은 이전 단계다.

- #2: 빈 파일·미지원 바이트·잘린 HWP를 네이티브 파서가 거부하는 자동 검사를 추가했다. 파일 선택 취소/권한 UI 검증과는 구분한다.
- #3·#9·#27: F2(2×2 표와 셀별 글자 서식), F3(합성 이미지), F4(다중 페이지)를 생성하고 각각 HWP/HWPX 저장→재열기 6건의 텍스트·객체·페이지 수를 비교했다. F1도 페이지 수 비교를 추가했다. 산출물은 `test-results/corpus/`와 `test-results/roundtrip/`이며 테스트로 재생성한다. 이미지 픽셀·폰트 렌더링·PDF의 시각 품질은 미검증이다.
- #26: 같은 문서 상태에서는 문단·표 카탈로그와 레이아웃 정보를 재사용한다. 네이티브 모델 객체, documentEpoch, changeSeq, documentSha256, layoutPageCount 변경 또는 분석 실패 시 폐기한다. 캐시에 문서 텍스트를 따로 저장하지 않는다.
- 실제 WASM 37페이지/33문단/63,991자 전체 읽기: 125개 응답, 레이아웃 조회 4,625→37회, 단일 측정 2,439→1,786ms. 정적 상태 어댑터를 쓴 엔진 측정이며 실제 host 지연 또는 peak 메모리 측정이 아니다. 재현은 `node scripts/benchmark-native-analysis.mjs`, 보고서는 `test-results/native-analysis.json`이다.
- #13·#16: 위 검사를 기본 자동 테스트에 포함했다. 기존 완료 조건 전체를 통과 처리하지 않는다. 아래 표의 39개는 이전 단계 기록이며 후속 검증은 44개다.

2026-09-14. macOS 실행은 팀원 담당이다. 아래는 자동 구현·검증과 사람의 최종 판정을 구분한 작업표이며 전체 이슈 완료 보고가 아니다. 로컬 변경본은 `fix/25-review-readiness`, 기준 main `9427866`이다. 코드 저장소에는 아직 커밋·PR이 없다.

대상 검색·선택 기능을 기존 비공개 Sites에 배포 완료했다. Sites 버전 4, 소스 `4655dcd2837b6a59c9d336c9c16577715833a170`, 배포 `appgdep_6aa7786f17e08191808975973108c9d8`, 상태 succeeded. 원격 GitHub main/설치된 플러그인 캐시 반영과는 별개다. 사용자 작업 탭은 재로드하지 않았다. 저장 후 새로고침하면 새 도구를 발견한다.

### 운영 기록 양식 (#23·#24)

첫 방문/재방문/업데이트별 `측정일, 최종 URL·빌드, 앱·브라우저 버전, 캐시 상태, 전송 바이트(압축 후), 준비 시간, 실패 건수/시도 수`를 기록한다. 빌드 파일 크기를 실제 전송량으로 대신 넣지 않는다. 월 예상 전송량은 각 방문 유형의 실측 평균 × 해당 방문 횟수의 합으로 계산한다. 지원 인원 수를 먼저 약속하지 않는다.

공개 확대는 계정 한도·초과 동작·예산·허용 데이터 범주·심사 접근이 확인된 뒤 결정한다. 미확인 동안 현재 비공개 범위를 유지한다. 한도/자산 로딩 오류가 나면 현재 열린 작업을 저장하도록 안내하고 자동 새로고침·캐시 삭제로 미저장 문서를 날리지 않는다. 서버 재사용은 로컬 개발 경로의 보조 검사이며 Sites 방문자가 서버를 실행해야 한다는 뜻이 아니다.

## 자동 증거 재현

`npm test`는 현재 39개 테스트이며 `desktop/roundtrip.test.mjs`가 `test-results/roundtrip/`에 F1과 `report.json`을 생성한다. 이 파일은 합성 데이터이며 원본 사용자 문서를 복제하지 않는다. 테스트는 Studio와 동일하게 `createBlankDocument()`로 기본 스타일을 초기화한다. `createEmpty()`만 사용한 초기 시험은 준비 단계 오류였으며 제품의 부분 서식 실패로 판정하지 않았다.

`npm run build`, `npm run verify:package`, `npm audit --omit=dev --prefix desktop`, `npm run benchmark:analysis`를 각각 실행한다. 엔진 roundtrip은 UI 다운로드/독립 뷰어/PDF 검사와 구분한다. 실제 IME와 시각 검증은 사람이 한다.
